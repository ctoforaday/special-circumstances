# proposed gap class — `structure-noncompliance` [PROPOSED — not in the registry until adopted]

Coined by `red-merge-r1` during `2026-08-23_sleeper-service-plan`. It is NOT staged into any later run:
an unreviewed class validating a future `--class` is the registry losing the only thing it
means. Adopting it means adding the slug to `feov-memory/class-registry.json` by hand.

- **definition**: the living report's analytical core omits a structural element the protocol's report template requires (e.g. a graded likelihood x impact x complexity risk matrix), carrying the raw material only as unordered prose
- **neighbour**: `risk-cross-term-ungraded`
- **distinguisher**: risk-cross-term-ungraded is two risks that ARE discussed but not jointly graded; structure-noncompliance is the ABSENCE of the required graded-matrix element entirely, for ALL risks, not just an interacting pair
- **first used on**: R1-7

The three fields above are the seat's own words, refused at the write if any were missing
(`record.validateClassNew`), so this proposal is well-formed by construction. What a
reviewer decides is whether it DISCRIMINATES — whether the distinguisher actually separates
it from its neighbour on a case where both are arguable.
