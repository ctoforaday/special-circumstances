# proposed gap class — `unflagged-inferential-transfer` [PROPOSED — not in the registry until adopted]

Coined by `red-merge-r3` during `2026-08-23_sleeper-service-plan`. It is NOT staged into any later run:
an unreviewed class validating a future `--class` is the registry losing the only thing it
means. Adopting it means adding the slug to `feov-memory/class-registry.json` by hand.

- **definition**: A citation's finding is applied to a materially different context than it was established in, as if it directly supports the report's claim, without the same explicit inference hedge the report attaches to its comparable sibling transfers in the same passage.
- **neighbour**: `derivation-status-overclaim`
- **distinguisher**: derivation-status-overclaim misstates HOW MANY independent sources/lanes corroborate a claim (a counting error); unflagged-inferential-transfer misapplies WHAT a single correctly-cited source actually established (a domain-transfer error), diagnosed by comparing a citation's hedge language against its sibling citations in the same paragraph.
- **first used on**: R3-2

The three fields above are the seat's own words, refused at the write if any were missing
(`record.validateClassNew`), so this proposal is well-formed by construction. What a
reviewer decides is whether it DISCRIMINATES — whether the distinguisher actually separates
it from its neighbour on a case where both are arguable.
