# An OCR citation carries its page, and red checks that page's pixels

Status: draft for the plan-auditor gate, 2026-09-11. It carries forward #644 and plans/local-ocr.md.
The human's three rulings bind the plan: (1) blue MAY cite OCR-derived text, and red verifies such
a citation against the page image ONLY when the citation has a page (no page means the tool output
is trusted); (2) red gets a ONE-PAGE lens verb, never whole-document `ocr pages`, and fetch keeps no
images; (3) where a page exists, enforcement is FIELDS + REFUSAL. Rulings of the same day, after the
first audit: (4) `--ocr-quote` is REQUIRED for a `leaf` citation of OCR-derived text; (5) the
page is rendered Chicago-style AT THE CITATION MARKER as "PDF p. 10" / "PDF pp. 10, 34", and the
Bibliography lists each source once with no pages. This plan follows the lead's proposal except
where the census contradicts it. §II names each departure.

## I. Summary & Goals

**The problem.** OCR text is deterministic and it can be wrong. Page 10 of IEEE 1012 reads
"Annexes A through J" where the scan says "I". A `cite` of OCR text records only the document
sha. The assembled `<sha>.ocr.txt` joins pages with `"\n\n"`, which looks the same as a
paragraph break, so nobody, blue included, can say which page a quote came from. Red has no
seat verb that produces pixels. So a misread is audited against the same misread text, and the
audit's "supports" means nothing.

**Goals.**

1. On an OCR-derived source, a cite records the page(s) its quoted span sits on, and the binary
   derives them. Blue never types a page.
2. A cite records whether its source text is OCR-derived, and the binary stamps that too. An
   old run's cite says "not recorded". It never reads as a plausible `false`.
3. Red can render ONE page of a cached scan at `tessocr.RenderDPI`, and gets its path.
4. A verify of a cite that has pages is refused unless it names a checked page whose image
   exists. The record holds the page and the image's hash.
5. Cites and verifies of non-OCR sources behave exactly as today.
6. A reader of the assembled report sees the page AT the citation marker, "PDF p. 10" or
   "PDF pp. 10, 34". The tool renders it from `Cite.pages` (ruling 5). The Bibliography lists
   each source once, with no pages.

**Success criteria (measured, §V).**

- A real-document test on IEEE 1012 records `pages == [10]` for the span "Annexes A through J"
  and refuses a span that is not in the reading.
- `render-page` writes p10 at 300 DPI. Its `render_sha` equals `reading.json`'s
  `render_shas[9]`.
- A `lens verify` on that cite without `--page` exits non-zero with the refusal sentence. With
  `--page 10` it records `page=10` and a 64-hex `page_render_sha`.
- A cite of an HTML source records `source_text_origin=embedded` and no pages. Its verify needs
  no `--page`.
- `go test -count=1 ./...` shows no failure outside main's baseline set. `cd scripts && go run
  ./golden`, the tagged engine suite, and the fuzz flag-coverage gate all pass.
- Every refusal added here fails a test when it is deleted (§V.6).
- In the IEEE 1012 test, the assembled report's marker for the p10 cite carries "PDF p. 10". The
  source appears once in the Bibliography, with no page. An HTML cite's NOTE is byte-identical to
  today's. The Bibliography's layout changes for every report (deduplicated list lines instead of
  `[^N]:` definitions), which ruling 5 requires.

**Non-goals.** Page derivation for text-layer PDFs: their text is the author's, and ruling 1 is
about OCR. Page checks on `corroborate`, where red found the source itself and there is no cite.
Page lists in the Bibliography (Chicago never carries pinpoints there). Printed-folio page
numbers, which the binary does not know. Fuzzy or OCR-error-tolerant matching.
Moving fetch's automatic OCR into `cite`.

## II. Technical Context

The code is Go 1.25 (go1.25.14 in ~/sdk), in the tools module
`plugins/frank-exchange-of-views/tools`. The OCR engine is `internal/tessocr` (cgo, behind the
`tessocr` tag; the tag-less build is a stub). Rendering is PDFium via wasm in `internal/fetchcache`
and needs no tag. The record is `internal/record/recordpb/record.proto`. Its bindings are
generated by `go -C scripts run ./protogen`. The SQL DDL is derived from descriptors
(`recordsql/schema.go`), and a repeated **scalar** field becomes a joinable child table
(`listTable`, schema.go:569). Repeated messages have no projection. The event-schema epoch is 6
(`requirements.json:3` → `record.EventSchema`, schema_gen.go:13). Nothing leaves the box: no
network beyond the fetch the seat already made, and no credentials.

**Four measured facts that reshape the lead's proposal.**

1. **The index's `ocr_derived` is never true.** `Entry.OCRDerived` (fetchcache.go:119) is set only
   from `Extraction.OCRDerived` (fetchcache.go:375). The PDFium extractor never sets that field
   (extractor.go:48 declares it; `grep -rn OCRDerived internal/fetchcache/pdfextract.go` → no
   write), and pdfextract_test.go:133 asserts that it is false. Fetch's automatic reading
   updates only the SUMMARY (`applyReading`, fetchsummary.go:92), never the index. Stamping a
   cite "from the fetch cache index" would record every OCR cite as not-OCR: the plausible zero
   facts-are-fields names. **Decision:** the cite derives origin from the index's
   `TextExtracted` plus the **reading record** (`ReadReadingRecord`, pageread.go). It deletes the
   two dead fields (§III.F).
2. **The `.pages/` directory gets cleared.** `RenderPages` runs `os.RemoveAll(PagesDir)`
   (pagerender.go:168), which takes the per-page readings and `reading.json` with it. The
   automatic path deletes `p????.png` there (readscanned.go:128-134). A one-page image written as
   `PagePath` would be deleted by either path and would pose as a partial `ocr pages` render.
   **Decision:** `render-page` writes to its own directory, `<run>/cache/<sha>.page-images/`.
3. **Lens verbs are role-wide.** `lens.Verbs()` (lens/command.go:20) is mounted for every
   `red-lens-*` seat (root.go:69). No mechanism scopes a verb to a lens area. The evidence-only
   prompt text is skills/research-protocol/scripts/debate.js:844, where `ledgerClause` is injected. Every lens can run `lens verify`, so every lens
   must be able to meet its refusal (§III.D).
4. **`pages` can be a repeated int; per-page pins cannot be a repeated message.** `listTable`
   takes scalars only. **Decision:** `repeated int32 pages` on Cite. The per-page render hash is
   pinned on the Verify, where it is one page's scalar, not a parallel array on the Cite.

**The data model after the change** (field numbers are the next free ones):

```proto
enum SourceTextOrigin {
  SOURCE_TEXT_ORIGIN_UNSPECIFIED = 0;  // refused at write
  SOURCE_TEXT_ORIGIN_EMBEDDED    = 1;  // the retrieved bytes carry the text: markup, plain text, a PDF text layer
  SOURCE_TEXT_ORIGIN_OCR         = 2;  // machine-read off page images by the local engine; it can misread
  SOURCE_TEXT_ORIGIN_NONE        = 3;  // the tool holds no text: a scan nobody has read
  SOURCE_TEXT_ORIGIN_NOT_RECORDED = 4; // written only by migrate: this citation predates the field
}
message Cite {   // + fields 11..15
  optional SourceTextOrigin source_text_origin = 11 [(sql) = {required: true, why: "..."}];
  optional string ocr_quote   = 12;   // blue's span, verbatim as typed
  repeated int32  pages       = 13;   // binary-derived, ascending, unique
  optional string ocr_engine  = 14;   // ReadingRecord.Engine the span was found in
  optional string ocr_text_sha = 15;  // ReadingRecord.TextSha: which reading
}
message Verify { // + fields next free
  optional int32  page               = N;   // --page: the page image red checked
  optional string page_render_sha    = N+1; // stamped: sha256 of the PNG on disk at verify time
  optional string reading_render_sha = N+2; // stamped: reading.json render_shas[page-1]
}
```

## III. Proposed Changes

### Decisions, each with the alternative it beat

**D1. Origin is an enum, not the lead's `ocr_derived` bool.** A bool collapses NONE (a scan with
no reading) and EMBEDDED (an author's text) into `false`. "false" on a scan nobody read claims the
text is trustworthy: the plausible zero. The enum mirrors `SourceOutcome`, where the zero means
nobody stated it and is refused. The name pairs with the existing `source_text_read`: that field
is how much blue read (seat-asserted), and this one is where the text came from (tool-stamped).
The vocabulary word "OCR-derived" stays: it is what `source_text_origin=ocr` means, and the fetch
summary keeps printing `ocr_derived` as it does now. **Derivation, first match wins.** EMBEDDED is
stamped only on positive evidence that the bytes carry text. `TextExtracted == nil` means "never
asked" (fetchcache.go:108-111), not "has text": non-PDFs leave `Attempted` false
(pdfextract.go:228), and a pre-field index line for a PDF (possibly a scan) is also nil.
1. `TextExtracted == true` → EMBEDDED. Fetch named the text layer to blue, and a forced operator
   OCR of that document is not what blue was handed.
2. A complete reading record exists (every page's `p%04d.txt` present, its sha equal to
   `PageReading.TextSha`) → OCR. This covers a legacy nil-`TextExtracted` PDF that fetch has read.
3. `NotRenderable == true` → NONE. A skeleton's text is the page furniture, not the source.
4. `TextExtracted == nil` and the media type carries text (`text/*`, `application/json`,
   `application/xml`, `application/xhtml+xml`, `+json`, `+xml`) → EMBEDDED. This is decided by a
   new `fetchcache.CarriesText(mediaType)`; no such helper exists today (`grep -n "func MediaType"
   internal/fetchcache/label.go:105` is the only media-type function).
5. Anything else → NONE: images, `application/octet-stream`, an unread scan, a legacy nil PDF with
   no reading.

A reading that is present but incomplete is NOT folded into NONE when an `--ocr-quote` is given.
The cite is refused with "the reading of <sha> is incomplete on disk — `fetch --url <u>`
re-derives it".

**D2. The span input is `--ocr-quote`, stored in `ocr_quote`.** The name was checked on every
surface. `--quote` is already the REPORT sentence (`flags.DescQuote`). "span" appears in 45
seat-facing files meaning a report span. "passage" is a report passage (seat/verbs.go:226).
`--source-text` is taken (how much was read). `ocr-quote`/`ocr_quote` have zero hits across
agents, skills, commands, docs, tools/internal, releasegate and integration. The compound limits
the flag to OCR, and so refusing it elsewhere reads naturally. **When it is required (ruling 4):**
origin=OCR AND `--source-text leaf`. A leaf cite of OCR text without it is REFUSED ("a leaf
citation of OCR-derived text names the span it quotes, with --ocr-quote, so the tool can record
its page"). It is accepted on OCR at `summary_only`/`unread`, and without it those cites carry no
pages and owe no image check (ruling 1). On EMBEDDED or NONE it is REFUSED, not dropped:
cite.go:138-140 records the earlier defect of a flag that was "registered and never read". The
refusal says why ("this source's text is not OCR-derived, so there is no reading to locate a
page in", or, for NONE, "`fetch --url <u>` reads the scan first").

**D3. Matching is whitespace-normalised and glyph-exact.** Both sides are compared after
`strings.Join(strings.Fields(s), " ")`. Case, hyphens, ligatures and punctuation must match. OCR
line breaks are layout, not text (p10's span sits mid-line, but its neighbour ends in "informa-").
A hyphen is a glyph the engine read, and a quote that drops it is not verbatim. *Beaten:* exact
bytes (fails every quote that crosses a line), dehyphenation (turns a real "tool-\nsupported" into
"toolsupported" and accepts text the reading does not hold), and NFC/case folding (widens the match
beyond what the reading says, which is the opposite of what an audit of a misread needs).
**Every refusal teaches.** Three cases are checked in order after a per-page miss:
(a) the span matches the page-joined text across a boundary → "your span runs from page 10 onto
page 11; quote the part on one page". Blue cannot see the boundary, since `"\n\n"` hides it, so
only the tool can say this. (b) it matches only when a line-end hyphen is joined → "found on page
N only as '<word->'; quote it as the reading has it". (c) otherwise → "not in the reading at
<text_path>", with the normalisation rule stated. Several single-page occurrences → **all pages
are recorded**. There is no minimum span length: no measurement backs a number, and whether a span
is adequate is red's to judge from the recorded `ocr_quote` (risk R4).

**D4. Pins are `ocr_engine` plus `ocr_text_sha`. No refusal on engine drift.** `run-archive/`
excludes the cache, so the event is the only place that outlives the container and can say which
reading located the page. On the lead's question: **a re-read under a new engine cannot move text
between pages.** Each page is read from that page's own pixels (`renderAndReadPages` loops
page by page), so the page number is bound to the pixels, not to the engine. A new engine only
changes whether the span is still *found*. If the new engine reads "I" correctly, the span
disappears from the reading, and the recorded page is still exactly where the old engine read
it. That is why verification is against pixels. The pin records which reading produced the
claim, and a later reading under another engine is visibly a different one.

**D5. The red verb is `render-page --sha S --page N`.** The name was checked on every surface.
`page` alone collides with "help page" (`manual` prints "every command's own help page") and with
`ocr pages`. `render` alone reads as the report's render (`show report`, `reportproj.Render`).
`render-page` has zero hits and follows the verb-noun shape of `count-claims`. It is a **real lens
verb**: `seat.New("render-page", …)` in `lens.Verbs()` (lens/command.go:20). It is read-only and
writes no event, which has a precedent in `near-match` (lens/nearmatch.go:28, `seat.New` with no
`seat.Records`). So it is mounted on the lens surface ONLY, never in root.go:220-233's branch
that every seat role shares. Its join key is `lens render-page`, per role and NOT in
`sharedAcrossSeats` (surface.go:132). Its help lives in `seat/help/render-page.md`, as for every
`seat.New` verb (seat/help.go:44 embeds `help/*.md`). It writes `<run>/cache/<sha>.page-images/p%04d.png` (grayscale, at
`tessocr.RenderDPI`, through a new exported one-page render in pagerender.go that reuses
`renderPagePNG`), and replaces an earlier file. It prints `path`, `dpi`, `render_sha`,
`page_text` (the `PageTextPath` for that page, so red sees the reading beside the pixels),
`reading_render_sha`, and `matches_reading: true|false`. Where no reading exists it prints
`reading: none` rather than an empty sha. It refuses an uncached sha (the `ocr pages` wording), a
non-PDF, and a page outside 1..pages. **Surfaces:** every lens seat, and no other. The operator
is not given it: the operator's pixels are `ocr pages`, and the operator never verifies. Mounting
a seat verb on the operator root would be a second tree for one contract. *Why every lens and
not only evidence:* `lens verify` is on every lens (fact 3), and D6's refusal binds any
lens that runs it. A refusal with no verb that satisfies it is a missing capability, and the
friction footer tells seats to log that and work around it. Chair (`spot-check` audits closures),
bench and blue do not verify, so they do not get it. *Beaten:* `--anchor c-… --page N` (binds to
the record, but red cannot then look at a neighbouring page for context), and a seat-visible `ocr`
group holding only `page` (two different trees both named `ocr`).

**D6. Verify takes `--page N` and stamps two hashes.** The refusals sit in `writeVerify`, because
they need the cite: (i) the cite has pages and no `--page` was given → refused, naming the pages
and the exact `render-page` command. (ii) `--page` is not in the cite's pages → refused.
(iii) `--page` on a cite with no pages → refused, because the page has no referent. (iv) no PNG
at the page-image path → refused ("render it first: …"). (v) the reading record is gone from the
cache → refused ("`fetch --url <u>` re-derives it"). The shape invariant (`page` set ⇔ both hashes
set) is checked in `record.go`'s validate, next to the Verify arm at :1282, because validate is
the single write path. A mismatch between the two hashes is **recorded, not refused**. Within one
binary the render is deterministic, so a mismatch means the reading came from another binary's
renderer, and the image still shows the page's content. Two fields on one record let any reader
compare them without recovering a string. One page is enough, because every recorded page holds
the whole span (D3 refuses straddles). `corroborate` gets no `--page`, since there is no cite.
**`--as unreachable` is exempt from (i) and (iv), on purpose.** That outcome records that red
could not read the source. For example, PDFium fails to render the page, in which case no image
can exist. Demanding one would make the honest negative unrecordable, and a verify that cannot be
written is worse than one that says nothing was checked. `--page` is still accepted with
`unreachable` (red rendered the page, and the pixels are illegible), and (ii), (iii) and (v) still
apply when it is given.

**D7. The epoch moves 6 → 7, and migrate states the miss.** CLAUDE.md:41 says to bump the epoch
when the event shape changes. `source_text_read` (a4bbf9bd) did not bump, because it was additive
and optional. This change is different on two counts. It adds a *required* Cite field, which an
old event lacks. And the constitutions will tell red to check a cited page's image, an ACT an
epoch-6 binary's tree cannot perform (G names the act and the field, never the command). New
prompts paired with an old binary would direct a seat to a capability it does not have, and
`setup`'s epoch check exists to refuse exactly that pairing. A `"cite"`
registry entry (migrate/entries.go) wraps `identityBody`. Where `source_text_origin` is absent, it
fills `NOT_RECORDED`, the enum form of the entries.go:147-164 stated miss. Old verifies need
nothing, because their new fields are optional and a Verify with no page is valid.

**D7a. A same-sitting correction carries every new Cite field unchanged.** #946 made CITE
correctable at `CORRECTION_TIER_PROSE`: only `title` and `text` are `(prose) = true`, and the
correction clones the prior act. `source_text_origin`, `ocr_quote`, `pages`, `ocr_engine` and
`ocr_text_sha` identify WHERE the quote sits, so each is `(prose) = false`. `cite.go`'s
correction path takes `--ocr-quote` from the prior act when it is not given, exactly as it does
`--quote`, `--url` and `--title`; a differing value is refused by the correction as a change to a
frozen field. The clone keeps the derived pages, so a correction never re-locates.

**D8. Delete the dead index field** (fact 1). Keeping a field that nothing writes, right beside
the one the cite now reads, leaves the trap for the next reader.

**D9. Fix fetch's `ocr_reason` hint.** fetch.go:135-137 tells seats to run `ocr pages`/`ocr read`,
which only the operator surface has (root.go:242-243). The new text is "automatic reading is off
(--ocr=false); fetch again without it to read the scan". That works on every surface.

**D10. The page renders in the note at the marker, and the Bibliography lists each source once
(ruling 5).**

*What exists.* `weaveCitations` (report/assemble.go:62-103) is called once per document
(report/docs.go:223). It rewrites each `<!--cite:c-…-->` into `[^N]`, numbered per LABEL, and
appends `## Bibliography` followed by one `[^N]: <title>. <url> (accessed <date>)` definition per
label (:84-100). **The note and the bibliography entry are therefore the same line, and a source
cited twice is listed twice.** That already breaks ruling 5's "once", before any page is added.
The live `show report` (reportproj.Render) keeps the invisible anchors and shows no note, so
only assembly renders one.

*The rendered form.*
- **Marker**: `[^N]`, numbered in first-appearance order, **one N per (URL, pages)**. Main's
  #946/#951 keyed notes per URL, so a red corroboration and a blue cite of one source no longer
  read "[^1][^2]" on one clause. Pages split that key: two cites of one PDF on different pages
  are two notes. **A pageless anchor adjacent to a paged anchor of the same URL takes the paged
  anchor's note** (gblock, 2026-09-15), so B9's doubled reference stays gone, and the existing
  `[^N][^N]` collapse reads it once. A pageless anchor with no such neighbour keys on
  (URL, no pages). A label with no source on the record keys by itself, as on main.
- **Note** (a footnote definition per key, placed directly after the body): today's full entry,
  with the locator in Chicago's position, after the title and BEFORE the URL and access date.
  - `[^N]: <title>, PDF p. 10. <url> (accessed <date>)`
  - `[^N]: <title>, PDF pp. 10, 34. <url> (accessed <date>)`. Pages come from `Cite.pages`,
    ascending, joined with ", ".
  - A cite with no pages keeps today's `[^N]: <title>. <url> (accessed <date>)`,
    **byte-identical**. The locator replaces the title's closing period with ", PDF p. N.", so
    the two forms punctuate alike.
  - The unresolved-citation note (:89) is unchanged.
- **Bibliography**: `## Bibliography`, then `- <title>. <url> (accessed <date>)`, **one line per
  URL**, in first-appearance order. It never carries pages. With no citations it is omitted, as
  today.
  - Red's supporting corroborations carry no sha (citationid.go:79-81). Keyed on (url, sha), they
    would print a second line for the URL blue cited, so they fold into that URL's line.
  - The line's title is the first blue cite's typed title for that URL (the first corroboration's
    title when no blue cite names it). Its date is the earliest access date across every cite and
    corroboration of the URL.
  - **A URL with two shas still renders as one line.** `Lookup` keeps the first index match per
    URL (fetchcache.go:187-190: "the first fetch's hash is canonical"), so a second sha appears
    only when a missing content file behind the index line is re-fetched. That is a cache repair,
    not a second source a reader could follow. The sha difference stays visible where audits read
    it: each cite's `sha256` in `show evidence`.

*Why this form.*
- **A full note rather than Chicago's short note ("Title, PDF p. 10").** A short note is
  ambiguous when two sources share a title, and it would change every existing report's notes.
  Chicago permits full notes alongside a bibliography.
- **"PDF p." rather than a bare number.** The source is cited by URL, and the binary knows the
  PDF page index, not the printed folio.
- **The Bibliography is keyed on URL.** The rejected keys:
  - *The rendered string* would list a source twice whenever it was cited on two different days,
    because the access dates differ.
  - *(url, sha)* would split blue's cite from red's corroboration of the same URL, because the
    corroboration has no sha.
  - *sha alone* would MERGE unrelated sources. One body can be served by many URLs: a bot wall,
    a login interstitial or a "no results" page collapses onto one content-addressed entry, and
    that is why `URLsSharingBody` exists (fetchcache.go:423-428). The URL is what the reader
    follows, so it is the key for "listed once".

  Nothing is lost by taking the first title, because each cite's own typed title stays in its
  note.
- **Notes placed as bare definitions after the body.** Proof notes already sit that way
  (`[^P%d]:`, report/proofs.go:81-84). No new heading means no new tool-owned section for blue
  to mis-author. GFM and the site renderer (report/md.go:353-355) collect definitions into the
  footnote list wherever they sit.

*Tool-rendered, never typed (the report-voice rule).* The pinpoint is composed only in
`weaveCitations`, from `record.Source.Pages`. A new field, filled in `citedSource`
(citationid.go:67-76) from `Cite.GetPages()`, is empty for red's corroboration Sources.
Seat-typed text is checked for process-voice tells in two places: at `ingest`
(cli/blue/ingest.go:128, `reportvoice.FindAll`) and on titles and spans (cli/blue/voice.go:30).
Neither sees assembly's output. So the tool-rendered pinpoint trips nothing, and blue typing
"PDF p. 10" into prose is the case that needs a rule. `reportvoice/tells.go` gains one tell:
"PDF pp?\. \d" in seat prose, advisory as every tell is (tells.go:14-17), with the message "the
tool renders a citation's PDF page at its marker from the record; a typed page is a second copy
that nothing keeps true". `grep -rn "reportvoice\." --include=*.go internal | grep -v _test`
returns only cli/blue (ingest.go:128-162, voice.go:30), so the tell reaches blue as an advisory
and nothing else. No red-side Go reader exists, and the plan claims none.

## IV. Risk & Mitigation (likelihood × impact × complexity-to-mitigate)

- **R1. Hand-built `Cite{}` fixtures go red when origin becomes required.** High × low × low. The
  census row says to re-run the grep and fix each fixture. The refusal is the point, so it is not
  relaxed.
- **R2. An operator's `ocr pages` run after a cite deletes the per-page readings the cite was
  located in** (pagerender.go RemoveAll). Medium × medium × low. The cite pins `ocr_text_sha`;
  verify refusal (v) says to re-fetch, and fetch re-derives the reading byte for byte. The page
  image lives outside `.pages/` (D5), so it survives.
- **R3. Blue fights the glyph-exact rule on hyphens and ligatures.** Medium × low × low. D3's
  refusals (b) and (c) name the exact form the reading holds. §V.3 asserts each sentence.
- **R4. A trivially short span ("the") records dozens of pages, and red checks one that is
  irrelevant to the claim.** Low × medium × medium. `ocr_quote` and `pages` are visible in
  `show evidence`, so red can FAIL the verify on the span's inadequacy. A length floor re-enters
  only with a measured case. It is listed for the human under Q2.
- **R5. The verify refusal blocks a lens that cannot render,** for example on a stub build
  without PDFium. Low × high × low. Rendering is PDFium wasm and needs no `tessocr` tag, so the
  stub build renders. §V.2 runs `render-page` tag-less.
- **R6. An epoch-6 run cannot be resumed under the new binary.** Certain × low × zero. The
  mechanism is not the epoch, which only `setup` compares. It is `recordsql/read.go`'s
  `olderColumns` (:429, :509, :519): the `cite` and `verify` tables gain columns, a run's schema
  is fixed at creation, and the read refuses with `olderRunAdvice` (:513), which names
  `migrate`. This is intended: `migrate` replays the run with the stated fill (D7), and §V.4
  migrates an archived run.
- **R7. A reading made by another binary's renderer gives `matches_reading: false`.** Low × low ×
  zero. It is recorded, not refused (D6), and the verb prints it.
