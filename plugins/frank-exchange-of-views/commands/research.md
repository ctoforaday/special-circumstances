Run a frank exchange of views on the topic in `$ARGUMENTS` (if no topic given, ask — do not guess). Parse optional flags: `--lanes` (blue candidate drafts, default 3; the engine enforces a floor of 3 unless `laneFloorOverride` gives a reason), `--max-rounds` (safety ceiling only — the real terminator is red-PASS or judged deadlock; default 12), and `--smoke` (pipeline exercise: sets `lanes: 1`, `maxRounds: 2`, `model: "haiku"`, **`judgmentModel: "haiku"`**, `laneFloorOverride: "smoke run — pipeline exercise only"`; use before merging debate-script changes). **`judgmentModel` is set EXPLICITLY here and that is the point of the mode.** Before both tiers were required, omitting it let the judgment seats inherit the session model, which measured 68% of the 2026-07-18 run's WALL CLOCK — 92 of 136 minutes across seven serial seats — so a "smoke" run was two-thirds full-strength and no faster to iterate on than a keeper. That lesson is why the engine now REQUIRES an explicit judgment tier (and bulk tier), inheriting neither: a mode that exists to be cheap and quick must say so for every seat, not only the bulk tier. `maxRounds: 2` because ONE round cannot exercise round-graduated lens dispatch or show citation collapse, which is most of what a pipeline exercise is for.

Prose here is for DECISIONS; the mechanics are scripted (design-by-contract: an LLM executing
mechanics is an unenforced good-faith contract). Your judgment calls: the topic, which corpora
it cites, the lane/round/model parameters, the launch, and the honest relay. Everything else
is two script invocations.

1. **Decide the run**: slug (`research/<yyyy-mm-dd>_<short-slug>/`), the cited corpora (each
   becomes a pin — for another run directory, cite its final round's commit), and whether any
   evidence needs manual staging into `inputs/` (e.g. a winnow list) — stage it BEFORE setup so
   the script keeps it.
2. **Set up the blackboard** (mechanics — `setup` is idempotent, keeps anything pre-staged,
   writes the `.run-live` marker for the hook guards, and does NOT create the red-merge-born
   artifacts):
   `<path to the feov-record executable> setup <run directory> --topic "<topic>" --model <resolved model> --judgment-model <resolved judgment model> --cite <path>[@pin] ... [--max-rounds <N> --lanes <N>] [--bin-dir <directory containing the feov-record binary>]`
   Pass `--bin-dir` whenever the binary the SEATS will call is not the one you are invoking here — it is the same directory you will hand the workflow as `binDir` in step 3. Omitting it checks this executable's own directory, which is correct for the normal launch. **The version preflight ALWAYS runs and always refuses on a miss**: it compares the binary against `recordToolVersion` in the `requirements.json` beside it, so a cache updated without a rebuilt binary fails HERE rather than mid-round. It used to be armed only by passing `--bin-dir`, which nothing did, and a skewed binary merely printed a warning and ran.
   `--model` and `--judgment-model` are REQUIRED — setup refuses without both (the engine never guesses or inherits a tier), so resolve them BEFORE this step and never omit either.
   Pass the SAME resolved config you will hand the workflow in step 3 (models per stage, the round ceiling, the lane count) — setup records it as the canonical `inputs/run-config.json` so the dashboard (and any post-hoc reader) can show which models ran at which stage and the ceiling in force, without being told separately. Relay its summary. `setup` VALIDATES every cite at its pin and refuses on a miss
   (W1.1) — a failure names the missing paths and the two remedies; fix and re-run, never
   work around. If gap-patterns reports "no
   memory dir", pass `--memory-dir <session project dir>/.claude/agent-memory/frank-exchange-of-views-red-auditor`
   — red's memory accrues under the LAUNCHING session's project, which may not be this repo.
   ACCESS PRECONDITION (W1.11): if the run directory lies outside the session's registered
   working directories, seat Glob/Grep will refuse it ("Path does not exist") — suggest the
   human run `/add-dir <repo root>` before launch, or accept that seats fall back to the
   sanctioned Bash grep path (slower, already priced into their prompts).
3. Invoke the **Workflow** tool with `scriptPath` = `${CLAUDE_PLUGIN_ROOT}/skills/research-protocol/scripts/debate.js` and `args` = `{ "topic": "<topic>", "runDir": "<run directory path>", "lanes": N, "maxRounds": N, "model": "<model>", "judgmentModel": "<model>", "laneFloorOverride": "<reason, only if lanes < 3>", "binDir": "<directory containing the feov-record binary>", "scorecards": <parsed contents of <runDir>/inputs/scorecards.json>, "gapPatterns": <parsed contents of <runDir>/inputs/gap-patterns-by-class.json> }` (`gapPatterns` is red's accumulated memory INDEXED BY CLASS: the engine hands a repairing seat only the patterns matching the class of the gap in front of it, because staging the whole corpus was measured worthless — run 5's lanes read it and committed the warned patterns anyway. `scorecards` is printed by setup, ready to paste — it USED to inject each chair's headline numbers into that chair's prompts, but priors-are-poison removed that cross-run SEED — a predecessor's numbers on a DIFFERENT question are Goodhart bait, topic-confounded and salience-priming. `scorecards` now feeds OPERATOR analytics only; `binDir` powers each chair's IN-RUN self-read — it runs `feov-record scorecard` against THIS run before its docket, seeing its own performance on the question in front of it, never a stale one. binDir activates record-tool DUAL-MODE and hands each seat its ROLE — omit it to run a legacy prompt set, e.g. resuming a pre-record run. **This is the ONLY switch that selects legacy mode**; `setup --bin-dir` no longer arms anything, it only says where the binary is, and setup's version preflight now runs unconditionally on every launch — a skewed binary fails at setup rather than mid-round, which is what step 2 promised while the check was opt-in and nothing opted in) (`model` and `judgmentModel` are REQUIRED — always pass both; the engine refuses to dispatch without them). Note the **Transcript dir** path the tool prints — step 5 needs it. **Model guidance (BOTH tiers REQUIRED):** `model` (the bulk tier — lanes, lenses, responses) and `judgmentModel` (the judgment tier — blue-synthesize, red-merge, judge, assemble) MUST both be set; the engine throws on either unset and never inherits the session model (setup refuses even earlier). Resolve the human's intent into two concrete models and pass both — if they gave neither or only one, ASK, do not guess a tier. Name a STRONG model for BOTH on a keeper run: red's lenses ride the bulk tier, and a cheap bulk model silently discounts the leaf-node verification that is load-bearing (retrospective §3 row 16b) — a cheap-bulk keeper is a mistake, not a shortcut. `--model sonnet --judgment-model sonnet` for development; `--smoke` sets both to haiku. On a RESUME, keep the original run's models — changing either busts the agent cache and re-runs completed rounds; a REDUCED `maxRounds` is the cache-safe stop-and-resume terminator (the standing practice — read the board telemetry, judge the stop yourself).
4. AFTER the workflow returns, relay its envelope verbatim (verdict, rounds, lanes, outstanding gaps) plus the run-directory path — YOU MUST NOT re-summarize the report's content; the report is the deliverable, and it is for the human. If the verdict is UNVERIFIED, say so plainly with the outstanding gap count — the gate never soft-passes, and neither does the relay. If the verdict is HALTED, the bench ended the run: relay the halt opinion VERBATIM and IN FULL from the envelope (halt_opinion) — it is addressed to the human and is never summarized, softened, or paraphrased.
5. **Capture the run record** (mechanics — journal copy, transcript tarball, cost.md with the
   telemetry join, the mechanized post-hoc audits, and `.run-live` marker removal):
   `<path to the feov-record executable> capture <run directory> <transcript dir>`
   `--bin` lets the record-backed audits (telemetry, record-parity, friction-parity) read the
   run through the tool's views (`show --view debate --json`, `--view friction`) instead of a
   markdown projection; omit it only for a pre-record legacy run, where those three SKIP.
   Relay `run-record-audit.md`'s verdict lines verbatim. A FAIL there is a run-record integrity
   finding (missing telemetry line, shard self-report diverging from disk, envelope friction
   that never reached the record) — report it like an UNVERIFIED: plainly, never smoothed over.
   Your judgment half: read the envelope's friction entries against the friction record (`show
   --view friction`) and dedupe attributed near-duplicates the parity check can't (same
   complaint, different wording).

**Monitoring a live run** (start this as a BACKGROUND task right after the Workflow launches — the watcher keys its lifetime to the .run-live marker and exits on its own when run-capture lifts it): `<path to the feov-record executable> dashboard <run directory> <transcript dir> --watch` writes `<run directory>/dashboard.html` (auto-refreshing) — board mass trend, open gaps by severity, live seats, cost-so-far, blackboard growth. The dashboard IS the record tool, so it reads the record in-process (no `--bin`); on a pre-record run whose record does not exist yet, the record tiles read "unavailable". The Workflow panel shows the phase; the dashboard shows the debate.
