## R4-1 — SECURITY: the §14.1 session corollary is "sound" only against an under-inclusive channel list; `Bash`-fetched / MCP-sidechain / in-repo-untrusted reads launder into untainted → auto-promotable, re-opening R1-3/R3-3 [severity HIGH, blocking-candidate]

- **Location:** §14.1 session corollary — *"a candidate concept is tagged `external-ingest` iff the session transcript contains **any** external read (`WebFetch`/`WebSearch`/external `file:`/`/ingest`) at or before the candidate's supporting turns — computed mechanically by the parser from harness-observed tool-use records … transitively."* and the soundness claim, §14.1 closing — *"This is not new machinery … and **it is sound**."* Cross-read against §14.3 — *"Taint is computed by the **parser** from the transcript's tool-use records — data the injection cannot alter."*
- **Problem — the invariant's soundness is enumerated, not general, and the enumeration has holes the attacker steers into.** "Transitive-after-any-external-read" is only sound if "external read" is the *complete* set of channels through which attacker-authored bytes enter a transcript. Blue instead fixes a **four-item denylist**, and at least three routine channels are outside it:
  - **(a) `Bash`-fetched content.** `Bash(curl evil.com)`, `Bash(gh pr view …)`, `Bash(gh api …)`, `Bash(git log)` of a remote-authored commit message, `Bash(cat downloaded_file)` — all pull external bytes into the transcript **as a `Bash` tool result**, which is not `WebFetch`/`WebSearch`/`file:`/`ingest`. A concept derived from that content is tagged `trajectory-derived` → **auto-promotable**. This is not hypothetical asymmetry: blue's own outbound secret-gate wires on **`WebFetch|WebSearch|Bash`** ([^LocalRepoScrub], §6.3) — the design *already treats `Bash` as a first-class I/O channel for the outbound direction* but omits it from the inbound taint list. The exfil channel and the injection channel are the same pipe; defending one end and not the other is the gap.
  - **(b) MCP tool results and sub-agent (sidechain) reads.** MCP servers (basic-memory is cited as an MCP precedent, §1.5/§7) and any custom MCP tool return remote content under a tool name the four-item list does not match. Worse, §1.4 notes sub-agent transcripts are separate **`isSidechain`** JSONL streams: a sub-agent that does a `WebFetch` produces its taint in the *sidechain*, and §14.1 never says the parent's extraction inherits taint from its sidechains. A poisoned page read by a research sub-agent launders into the parent's "clean" reasoning.
  - **(c) In-repo files read via `Read`, authored by untrusted commits.** The corollary taints "external `file:`" reads. A file **inside the current/cloned repo** — a poisoned source file from a merged malicious PR, or a cloned repo's own tree (R1-2/R3-2) — is read via `Read` and is not naturally "external." The **import corollary** clamps the cloned *knowledge store's* committed trust fields, but it does **not** taint a concept the agent *derives* by reading poisoned *source* during a session. So the R1-2 clone vector re-enters through session-derived concepts, below the import corollary's reach.
- **Why this is the keystone, not a detail:** §14.1 is the fix blue built to close R3-1/R3-3/R3-7/R3-5/R3-9 "by construction." If the taint under-tags, then (i) R3-3/R3-7 laundering is re-opened through channels (a)-(c); (ii) R3-1's authorship-demotion loses its safety net (local re-derivation can corroborate laundered-untainted content); (iii) R3-5's "cross-project blast radius bounded to candidate-tier" leaks (see R4-2). The word **"sound"** (line 1474) is the over-claim — the mechanism is sound *relative to a denylist*, and a denylist is the wrong structure for a taint boundary.
- **Required fix:** invert the enumeration — treat taint as **allowlist-based**: a candidate is `trajectory-derived` **only if every supporting turn is authored by the operator or the harness's own reasoning with no intervening tool result carrying external bytes**; *any* tool result (`Bash`, MCP, sidechain, non-project `Read`) whose provenance is not operator/harness taints transitively. Enumerate what is *trusted*, not what is *external*, so a newly-added tool defaults to tainted. Explicitly define "external `file:`" to include in-repo files not authored by a locally-trusted commit. And propagate sidechain taint into the parent. If a complete allowlist is infeasible, **withdraw the "sound" claim** and grade the residual honestly as R3-4 was.
- **Grade:** likelihood **high** (`Bash(gh/curl/git)` and reading cloned-repo source are routine in agent sessions — the attacker's cheapest laundering path) · impact **high** (auto-promotion of laundered poison to active/instruction authority, persistent, cross-project via R4-2) · complexity-to-fix **medium** (allowlist inversion is a parser change, not research; sidechain propagation is plumbing). Corroboration of blue's "sound"/"mechanical" claim as written: **contradicted** — the design's own outbound gate proves `Bash` is a channel the inbound taint omits. **Pattern (new): invariant-soundness-by-enumeration** — a keystone invariant sold as "sound/mechanical" whose soundness actually rests on an under-inclusive channel *denylist*, provably incomplete because the system's *own* symmetric defense already treats an omitted channel as I/O.

## R4-2 — GRADE/COMPOUNDING: R3-5's reconciliation misattributes the widening-#2 bound — the import corollary does NOT fire within the operator's own global store, so blast radius after a single clearance is every project at active authority [severity MEDIUM, feeds lead's docket]

- **Location:** §14.7 (R3-5) — *"(2) the **import corollary** means a concept propagating to another project **re-derives trust locally in the receiving project** — it arrives as reference-tier data, not active authority. So widening-#2's 'bounded to candidate-tier reference until it clears the gate' **holds under the adopted invariant**."* Cross-read against §14.7 (R3-8) — *"§13.7's load-bearing value is the operator's **own cross-project global store** … **one repo the operator authors**"* and §14.1 import corollary — *"On clone/pull/merge of any store **whose commits are not locally authored**, every concept loads clamped to reference/candidate tier."*
- **Problem:** the import corollary only fires on a store **whose commits are not locally authored** (a foreign clone). But widening #2 — the one widening blue accepts as "the gated price of core value" — attaches to the operator's **own global store**, whose commits *are* locally authored (`/dream` commits under the operator's identity, §13.2/§14.2). That store is one repo `@`-imported into every project's context; a concept promoted to `active` there renders into the projection every project loads. There is **no per-project re-derivation** for the own-global-store case — the receiving project simply imports the projection. So R3-5's reconciliation invokes a mechanism (import-corollary per-project re-derivation) that **does not apply** to the store carrying widening #2. The actual bound is a **single ingest gate** (session-corollary taint + mit.2 at first surfacing), not a per-project clamp. Consequence: once a poisoned concept clears that one gate — e.g. via the conceded irreducible residual, an operator `/remember`-ing screened-but-actually-poisoned content (§14.2c), whose frequency now *rises* under R4-3 — it is `active` in the global store and broadcasts to **every project at active authority**, with no second gate. The blast radius blue graded as "bounded to candidate-tier reference" is, post-clearance, active-authority-everywhere.
- **Required fix:** correct §14.7 to state the own-global-store bound honestly — it is a **single ingest-time gate**, not per-project re-derivation (the import corollary is a foreign-clone mechanism and does not fire here). Then either (a) grade widening #2's post-clearance blast radius at active authority explicitly (every project, persistent), or (b) add a per-project activation gate for global-store concepts so the "re-derives locally" claim becomes true, or (c) route global-store projections through a per-project ratification akin to the clone gate. Combined with R4-1, the "candidate-tier bound" leaks at *both* ends: under-tagging lets poison in as trajectory-derived, and no per-project re-derivation stops it broadcasting once in.
- **Grade:** logic/meta, compounding · likelihood n/a · impact **medium** (weakens the single mitigation the lead's docket closure conditioned widening #2 on; the accepted price is higher than §13.7 states) · complexity-to-fix low (honest re-grade) to medium (if a per-project gate is added). Corroboration: the import corollary's own "not locally authored" trigger, quoted at the leaf node, does not cover the locally-authored global store. Does **not** re-open the lead's classification (three widenings counted net-new — closed); flags that the *mitigation* the closure rests on is misattributed. **Pattern: risk-grading conflation (verdict/docket-keystone leaning on a mitigation that does not fire for the case it is invoked to bound).**

## R4-3 — TRADEOFF/COHERENCE: R3-3's auto-promotion downgrade (§14.3) silently lowers the value side of the §13.7 build-vs-adopt accounting the lead closed, and relocates elevation onto `/remember` at higher volume — re-creating the §2.4 review-fatigue dynamic [severity MEDIUM, flag for lead]

- **Location:** §14.3 — *"Auto-promotion is downgraded from a load-bearing feature to a **convenience** that operates only on (i) **fully-untainted sessions** (no external read at all) and (ii) **operator-confirmed** concepts … Any web-touched session's derived concepts are `external-ingest` → **human-gated**, never auto-promoted."* Cross-read against §13.7 value ordering — *"**Typed concepts + human-gated promotion to skills** … the observation→rule-skill ladder is the plugin's mechanism"* (**LOAD-BEARING**) — and §2.4's own finding that diligence-dependent review decays to LGTM.
- **Problem — two coupled coherence defects the Round-3 concession introduced.**
  - **(a) The value side moved after the docket closed.** The lead closed R1-8/R2-2 in Round 2 on an accounting (§13.7) that counted "typed concepts + skill-promotion" as one of *two* load-bearing differentiators — and that ladder is *capture → corroborate → promote → decay*, with **auto-promotion on recurrence** as the "corroborate → promote" engine (§2.2/§5: "promote on recurrence, `review_count ≥ 2`"; Heilmeier Q5: "Learning **compounds** across projects"). §14.3 then downgrades auto-promotion to fire **only on fully-untainted (no-external-read-at-all) sessions** — which, given that "**almost every real session touches the web**" (blue's own §13.4 premise), means recurrence-driven auto-promotion **almost never fires in practice**. The compounding-learning value proposition now reduces to manual `/remember` curation. This is a material narrowing of the *value* side of a go/no-go accounting that was closed **before** the concession — the netted margin the lead accepted was computed on a promotion ladder Round 3 partially gutted. Not a re-litigation of the *classification*; a notice that a load-bearing value input degraded after closure.
  - **(b) Elevation relocated onto `/remember`, at higher volume — the §2.4 dynamic returns.** With web-informed auto-promotion removed, the **only** path for the common case (web-informed insight) is the operator manually `/remember`-ing it. So `/remember` volume rises sharply — and §14.2c already concedes the irreducible residual is "operator manually `/remember`-confirms specific poisoned content." Higher `/remember` volume → the exact volume-driven LGTM decay §2.4 documents → **increased frequency of the conceded residual**. mit.3 body-screening is heuristic (imperative verbs, "ignore previous"); a poisoned *fact* that is not instruction-shaped ("the canonical endpoint is `evil.example/api`") passes screening and gets `/remember`-ed by a fatigued operator. The R3-3 fix (conservative taint) is safe against *auto*-promotion but pushes the risk down onto a *manual* path whose failure mode is the one the report already measured.
- **Required fix:** (1) re-state to the lead that the §13.7 value side moved — the "skill-promotion ladder" load-bearing credit now rests on *manual* promotion, not automatic recurrence; either re-affirm the build margin on the reduced value or note it narrowed. (2) Grade the `/remember`-volume-vs-fatigue interaction: apply the §2.4 forensic/structural controls (weekly digest, per-batch caps, tier-gated review) to `/remember` as they are applied to `/dream`, since `/remember` is now the primary elevation path and inherits §2.4's decay risk.
- **Grade:** likelihood **medium** (web-touched sessions are the norm; `/remember` becomes the default elevation path) · impact **medium** (compounding-learning value degrades toward manual curation; conceded poison-residual frequency rises) · complexity-to-fix **low** (re-state the margin; extend §2.4 controls to `/remember`). Corroboration: §14.3's "fully-untainted (no external read at all)" against §13.4's "almost every real session touches the web" — blue's own two premises. **Pattern: self-defeating mitigation (a control added to close a prior gap relocates the risk onto a path — manual `/remember` — whose discredited-diligence failure mode the report already established, and lowers a closed accounting's value side).**

## R4-4 — COHERENCE: the invariant names `last_seen` as non-inheritable but the import corollary omits it from the reset list — a foreign concept imports with an attacker-set `last_seen`, resetting its decay clock [severity LOW]

- **Location:** §14.1 invariant header — *"No trust-elevating field — `status`, provenance tier, `review_count`, **`last_seen`** — is ever inherited from bytes an attacker could author."* vs the import corollary's reset list — *"its committed `status`/tier/`review_count` are **reset to candidate baseline**."* (`last_seen` is named in the invariant but absent from the reset enumeration.)
- **Problem:** `last_seen` drives decay/eviction (§6.1: eviction-by-unretrievability over 14/60-day windows). If a cloned/foreign store's concepts import **without** `last_seen` being reset (the corollary resets only status/tier/`review_count`), an attacker sets `last_seen` to a fresh timestamp so a stale/abandoned poisoned concept **resets its decay clock** and survives in the receiving store far longer than a genuinely dormant concept would. Low impact on its own (the concept is still clamped to reference tier, so it does not gain authority), but it is a stated-but-unexecuted leg of the invariant — the exact "retract-by-annotation vs actual edit" discipline gap red has flagged before, here between the invariant's *claim* and its *corollary's mechanism*.
- **Required fix:** add `last_seen` to the import-corollary reset list (reset to import time or clear it), so the corollary actually enforces every field the invariant names.
- **Grade:** likelihood low-medium (only on import of a foreign store, a nice-to-have-feature case) · impact low (decay-clock manipulation on already-reference-clamped data) · complexity-to-fix trivial (one field in the reset list). Corroboration: the invariant's own field list vs its corollary's reset list, quoted at the leaf node — an internal mismatch.

## Synthesis for this lens

Blue adopted red's Round-3 meta-recommendation — one information-flow invariant replacing six
spot-patches — and that is genuinely the right move; §14.1 is more coherent than the Round-1/2
gate-by-gate design, and R3-6 closes clean, R3-4 is honestly graded-open, R3-2/R3-9 are sound
analytic work. Severity continues to decline: Round 1 had a verified-false claim plus three new
security vectors; Round 4 has one enumeration hole in an otherwise-sound invariant plus three
coherence/grade residuals. This is convergence, not flailing.

**But the keystone is over-claimed.** The invariant is asserted **"sound"** (line 1474) and
**"mechanical"** when its soundness rests on a four-item *denylist* of external-content channels
(**R4-1**) that omits `Bash`-fetched bytes — a channel the design's *own outbound secret-gate already
treats as I/O* — plus MCP/sub-agent-sidechain reads and in-repo untrusted-`Read`. Through each, poison
launders into an untainted, auto-promotable concept: the R1-3/R3-3 laundering the invariant exists to
close, re-opened one layer down. Every Round-3 closure that leans on the invariant (R3-1
authorship-demotion, R3-3/R3-7 taint, R3-5 blast-radius bound) is therefore **contingent on a
soundness the design does not yet have**. The fix is a parser change (invert to an allowlist so new
channels default to tainted), not research — so this is a hardening gap, not a redesign.

**Compounding into the (closed) docket, not re-litigating it:** **R4-2** — R3-5's "bounded to
candidate-tier" reconciliation misattributes the bounding mechanism (the import corollary does not
fire for the operator's *own* global store, so post-clearance blast radius is active-authority in
every project); **R4-3** — the R3-3 auto-promotion downgrade lowered the *value* side of the §13.7
accounting the lead closed, and relocated elevation onto `/remember` at higher volume, re-importing
§2.4's review-fatigue failure mode. Both are notices to the lead that inputs to the closed go-decision
moved after closure; neither re-opens the classification.

**Blocking-candidate this lens:** R4-1 (invariant soundness-by-enumeration — `Bash`/MCP/sidechain/
in-repo taint holes, "sound" over-claimed). **Feeds the docket:** R4-2, R4-3. **Low/coherence:** R4-4
(`last_seen` named-but-not-reset). No new gap is closed, rebutted, or risk-accepted → **no PASS**.
